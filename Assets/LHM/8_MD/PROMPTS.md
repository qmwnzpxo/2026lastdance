# PROMPTS.md — 지시문 모음 (UnMachine / Unity 6)

슬래시 명령이 있는 환경에서는 명령을 쓰고, 없는 환경(웹 채팅 등)에서는 아래 지시문을 복사해서 쓴다.
`< >` 부분만 바꿔서 붙여넣는다.

**지시 전 체크:** 이전 작업은 현민이 직접 커밋해서 `git status` 를 깨끗하게 해 둔다. (`docs/REVIEW.md` 만 남은 건 괜찮음)
**AI는 커밋하지 않는다.** 모든 지시문에서 Claude는 "커밋 제안"만 HANDOFF에 적는다.
**검증은 현민이 씬에 배치해서 한다.** Claude는 Unity를 실행하지 않고 "에디터 작업"과 "씬 테스트 절차"를 쓴다.

## 좋은 요청의 7요소 (토큰 절약)

| 요소 | 내용 | 예 |
|---|---|---|
| 목표 | 한 번에 하나만, 한 문장으로 | 보스 2페이즈 진입 로직 추가 |
| 대상 | 바꿀 파일·범위를 먼저 지목 | `Core/Boss/BossPhase.cs`, `BossConfig.cs` |
| **기획서 근거** | `docs/spec/` 의 파일과 장 | `spec/boss.md 6-2, 10-1` |
| 근거 | 에러 로그, 재현 방법, 현재 동작 | 체력 50%에서도 1페이즈 유지됨 |
| 제약 | 범위 밖, 지켜야 할 것 | 1페이즈 패턴은 건드리지 않음 |
| 출력 형식 | 답변 길이·형태 | 짧게, 변경 파일 먼저 |
| 검증 방법 | 씬에서 무엇을 보면 되는지 | 체력 250/249에서 페이즈 디버그 라벨 확인 |

- "좋게 해줘" 대신 "무엇을, 어디서, 어떤 기준으로"를 쓴다.
- 배경 설명은 반복하지 말고 `docs/HANDOFF.md`, `docs/BACKLOG.md`, `docs/spec/` 를 참조하게 한다.
- 요청이 길고 막연하면 먼저 `/prompt-expert` (5번 지시문)로 다듬는다.

## 1. Claude에게 새 작업 지시 (일반 모드)

```
AI_RULES.md와 docs/HANDOFF.md를 먼저 읽어줘.
작업 착수 전에 현재 커밋 해시를 docs/HANDOFF.md의 "기준 커밋"에 먼저 기록해줘.

[작업] <무엇을 만들지 한 줄, 또는 BACKLOG 작업 ID (예: T3)>
[기획서 근거] <docs/spec/<파일>.md 장 번호>
[대상] <바꿀 파일·범위 (Core / Runtime 구분)>
[상세]
- <동작 1>
- <동작 2>
[완료 기준]
- <이렇게 되면 완료>
[범위 밖]
- <이번에 건드리지 말 것>
[튜닝 값]
- <SO에 넣을 필드와 초기값. 모르면 "기획서 수치로, 없으면 적당히 정하고 HANDOFF에 기록">

구현 전에 5줄 이내 계획(씬에서 확인할 방법, 예상 에디터 작업 포함)부터 보여주고,
끝나면 정적 점검 → docs/HANDOFF.md 갱신(에디터 작업, 씬 테스트 절차, 커밋 제안)까지 해줘.
Unity는 실행하지 말고, 커밋하지 마. 씬 테스트와 커밋은 내가 할게.
보고는 짧게: 변경 파일 → 동작 변화와 리스크 → 정적 점검 → 에디터 작업·씬 테스트 요약 → 커밋 제안.
```

**예시**
```
[작업] 보스 페이즈 판정 (BACKLOG T1)
[기획서 근거] spec/boss.md 6-2, 10-1
[대상] Core/Boss/BossPhase.cs(신규), Runtime/Boss/BossConfig.cs, Runtime/Boss/BossDebugView.cs(신규, 디버그 표시)
[상세]
- 체력 50% 미만에서 2페이즈, 최초 1회만 전환 (중복 방지 플래그)
- 전환 시 PhaseChanged 이벤트
[완료 기준]
- 씬에서 체력 250이면 1페이즈 유지, 249면 2페이즈 전환, 다시 전환되지 않음 (디버그 라벨·로그로 확인)
[범위 밖]
- BT 교체, 발사체 회수, 카메라 이펙트 (T3에서)
[튜닝 값]
- BossConfig._phase2HpRatio = 0.5
```

## 12. 기획서 → spec md 변환 (Claude에게)

```
첨부한 기획서(docx 또는 붙여넣은 본문)에서 <챕터 이름> 부분만 docs/spec/<파일>.md 로 정리해줘.
docs/spec/README.md 의 변환 규칙을 따라:
- 기획서 문장을 바꾸지 말고 표·목록 형태만 정리
- 수치는 표로 모으기
- 다른 챕터와 걸치는 내용(예: 보스룸 공간 규격, 보스 UI)도 이 시스템 것이면 가져오기
- 기획서 안의 불일치는 맨 끝 "원문 점검 메모"에 적고 임의로 고르지 않기
- 맨 위에 원본 버전(<1002.4v>)과 날짜 적기
코드는 건드리지 말고 docs/spec/<파일>.md 와 README 표 상태만 수정해줘. 커밋은 내가 할게.
```
