# spec-check

> `.claude/skills/spec-check/` 와 `.agents/skills/spec-check/` 에 같은 내용으로 둔다.

## 입력

- 대상 기획서: HANDOFF "기획서 근거" 또는 현민이 지목한 `docs/spec/<파일>.md` 의 장
- 대상 코드: 변경 diff, 또는 지목한 `.cs` (특히 `*Config` ScriptableObject와 Core 로직)

## 절차

1. 기획서 해당 장에서 **수치**(체력, 시간, 거리, 확률, 횟수)와 **규칙**(조건, 순서, 예외 처리)을 목록으로 뽑는다.
2. 코드에서 대응하는 곳을 찾는다.
   - 수치 → `*Config` 의 필드 초기값과 `Tooltip`/주석의 `spec:` 표기
   - 규칙 → Core 로직의 조건문·상태 전이, 그리고 HANDOFF "씬 테스트 절차"에 그 규칙을 확인하는 줄이 있는지
3. 각 항목을 판정한다: ✅ 일치 / ❌ 불일치 / ➖ 구현 범위 밖 / ❓ 기획서 자체가 모호·충돌(기획서 "원문 점검 메모" 확인)
4. 단위 변환은 근거와 함께 확인한다 (예: "무적 12프레임" ↔ `0.2f` 초 @60fps).
5. 아래 형식으로만 보고한다.

```
| 기획서 (파일 장) | 기획 내용 | 코드 위치 | 코드 내용 | 판정 |
|---|---|---|---|---|
| boss.md 4장 | 체력 500 | BossConfig.cs:12 | _maxHp = 500f | ✅ |
| boss.md 6-5 | 2페이즈 휴식 1초 | BossConfig.cs:20 | _restPhase2 = 1.5f | ❌ |
| boss.md 6-3 | 원거리 X<30 | ComboSelector.cs:31 | dist >= 30 | ❓ 기획서 조건 겹침 (13장) |
```

불일치 요약 한 줄 + 씬 테스트 절차에서 확인하지 않는 규칙 목록을 덧붙인다.

## 하지 않는 것

- 코드나 `docs/spec/` 를 고치기 (구현 담당이 반영하고, 기획서는 현민이 고친다)
- 기획서가 모호한 항목을 임의로 해석해서 ❌ 판정하기 → ❓로 두고 질문 목록에 넣는다
