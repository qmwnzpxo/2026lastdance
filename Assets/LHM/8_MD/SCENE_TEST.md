# docs/SCENE_TEST.md — 씬 배치 테스트 가이드

> 언머신의 검증은 **현민이 Unity 에디터에서 씬에 직접 배치해서 플레이**하는 것으로 한다. (AI_RULES 6장)
> AI는 Unity를 실행하지 않는다. 대신 현민이 바로 따라 할 수 있는 **씬 테스트 절차**와 **디버그 표시**를 준비한다.
> 절차는 작업마다 `docs/HANDOFF.md` 5·5-1번에 쓰고, 형식은 `scene-test-writer` 스킬을 따른다.

---

## 1. 테스트 씬

| 씬 | 용도 | 비고 |
|---|---|---|
| `Test_Sandbox` (제안) | 기능 하나씩 확인하는 빈 방. 바닥·벽·플레이어만 있음 | 현민이 만든다. 작업마다 이 씬에 대상 오브젝트를 배치 |
| `Test_Boss` (제안) | 보스룸 규격(가로 40 × 세로 30 Unit) 그대로 | spec/boss.md 2장 |
| 실제 스테이지 씬 (`Stage1-1` 등) | 통합 확인 | 기능이 샌드박스에서 통과한 뒤 |

- 테스트 씬은 실제 씬을 망가뜨리지 않으려고 따로 둔다. 커밋할지는 현민이 정한다.

## 2. 현민의 확인 순서 (매 작업)

1. 에디터로 돌아와 **컴파일이 끝날 때까지 기다린다** → Console에 빨간 에러가 있으면 원문을 Claude에게 붙인다 (PROMPTS.md 6번).
2. HANDOFF "에디터 작업"대로 SO 에셋 생성·참조 연결·배치를 한다.
3. HANDOFF "씬 테스트 절차" 표를 위에서부터 진행하며 결과 칸에 ✅/❌를 적는다 (또는 결과만 Claude에게 말한다).
4. 경계 상황을 꼭 한 번씩 해 본다.
5. 플레이를 멈춘 뒤 Console에 경고·에러가 남았는지 본다 (Collapse 켜기).
6. 결과를 Claude에게 알린다 → Claude가 HANDOFF "현민 씬 테스트 결과"에 기록한다.
7. 괜찮으면 현민이 직접 커밋한다 (HANDOFF "커밋 제안" 참고, `.meta` 함께).

## 3. 디버그 표시 규칙 (Claude가 코드로 준비)

씬에서 눈으로 확인하기 어려운 값은 Claude가 디버그 표시를 같이 만든다.

| 확인하고 싶은 것 | 방법 |
|---|---|
| 판정 범위·시야·콤보 거리 | `OnDrawGizmosSelected` 로 원·부채꼴·박스 그리기 |
| 현재 상태·페이즈·선택된 콤보·남은 타이머 | 인스펙터에 읽기 전용으로 보이는 디버그 필드, 또는 Scene 뷰 라벨(`Handles.Label`, `#if UNITY_EDITOR`) |
| 상태 전이·이벤트 발생 시점 | `GameLog` 한 줄 (`[Boss] Phase 1 → 2 (hp 249/500)`) |
| 경계 상황 만들기 | 인스펙터 `[ContextMenu]` 버튼 (예: "체력 250으로", "드론 소환 강제") |
| 재현 | `IRandom` 시드를 인스펙터에서 고정 |

- 디버그 코드는 `#if UNITY_EDITOR` 또는 `[Conditional("UNITY_EDITOR")]` 로 감싸서 빌드에 들어가지 않게 한다.
- 디버그용 `[ContextMenu]` 는 게임 규칙을 우회하는 치트이므로 메서드 이름 앞에 `Debug_` 를 붙인다.

## 4. 결과가 실패일 때 Claude에게 줄 것

```
[씬 테스트 실패] HANDOFF 5-1번 #<번호>
[실제] <무슨 일이 일어났는지>
[Console]
<에러·경고 원문 그대로>
[씬 상태] <어느 씬, 어떤 오브젝트, 인스펙터 값 바꾼 것>
```

## 5. 자동 테스트를 원할 때

자동 테스트(EditMode / PlayMode)는 **현민이 요청할 때만** 작성한다. 로직이 `UnMachine.Core` 의 순수 클래스로 분리돼 있으므로 나중에 붙이기 쉽다.
